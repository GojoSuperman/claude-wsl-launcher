# Claude WSL Launcher

[한국어](README.md) · [English](README.en.md) · **日本語**

WSL の中で動く小さなローカルダッシュボードです。`~/projects` 配下のフォルダーをカードとして表示し、
ボタン一つでそのフォルダーから **Claude Code（`claude`）を新しい WSL ウィンドウ** に起動します。
各カードには git の状態・実行中かどうかを表示し、リモート（GitHub）からの取得・新しいプロジェクトの作成もダッシュボードから行えます。
ダッシュボード下部には **このサーバー自身のコンソール** が表示され、閉じるときにサーバーも終了する必要があることを確認できます。

> 初めての方はこちら → **[セットアップガイド](docs/SETUP.ja.md)**

## なぜこのツールか？

`claude` は **WSL ネイティブパス**（`~/projects/...`、ext4）から起動して初めて、正しく・高速に動作します。Windows エクスプローラーで `\\wsl.localhost\...`（UNC パス）に入ってそこから起動すると、次の落とし穴にはまります：

- 「このフォルダーを信頼しますか？」の再確認が繰り返される
- claude の Bash が **Windows Git Bash** として動き、Linux の `node_modules` バイナリと競合
- セッションログが Windows 側（`C:\...`）に別途たまる
- 境界をまたぐファイル I/O（`npm install`・`git status` など）が **5〜10 倍遅い**

このツールは毎回ターミナルで `cd … && claude` と打つ手間なく、**常に正しいネイティブ WSL ウィンドウでワンクリック起動**し、これらの落とし穴を回避します。

## ⚠️ 動作要件

このツールは **ローカル PC を直接操作**します（ファイルスキャン・WSL ウィンドウの起動）。そのため、以下の環境でのみ動作します：

- **Windows 10/11 + WSL2**（`wsl.exe`・`powershell.exe` を使用 → **macOS・ネイティブ Linux は非対応**）
- WSL ディストリビューション内に **Node.js 20 以上**（nvm 推奨）
- WSL ディストリビューション内に **Claude Code CLI**（`claude` コマンド）— このツールが起動する対象

ディストリビューション名・ホームディレクトリ・ユーザー・デスクトップのパスは **実行時に自動検出**されるため、PC ごとに設定を変える必要はありません。

## クイックスタート

> ⚠️ **すべてのコマンド（クローン・インストール・ショートカット）を WSL（Ubuntu）ターミナル内で**実行してください — Windows PowerShell やコマンドプロンプトではありません。PowerShell からクローンすると `.sh` ファイルが Windows の改行コード（CRLF）で保存され、ショートカット作成が `set: pipefail: invalid option name` で失敗します。

```bash
# WSL ターミナルで（ツールはスキャン対象フォルダーの外に — 例: ホーム）
cd ~
git clone https://github.com/GojoSuperman/claude-wsl-launcher.git
cd claude-wsl-launcher
npm install
npm start
# ブラウザ: http://127.0.0.1:41730  （既定で ~/projects をスキャン。無ければ mkdir -p ~/projects）
```

ポート変更: `PORT=5000 npm start`（ポートが使用中なら 41730→41739 の順に自動フォールバック）

スキャンフォルダ変更: `PROJECTS_ROOT=~/dev npm start`（既定は `~/projects`）

詳細な手順（環境確認・インストールを含む）は **[セットアップガイド](docs/SETUP.ja.md)** を参照してください。

### デスクトップショートカット（オプション）

```bash
bash scripts/install-shortcut.sh
```

デスクトップにショートカットが作成されます。ダブルクリックすると **サーバーをバックグラウンドで起動し、ブラウザだけ** を開きます（別途ターミナルウィンドウは開きません）。サーバーの起動に失敗した場合のみ、ログウィンドウが表示されて原因を確認できます。

## 機能

- **カード一覧**: `~/projects/*` フォルダーをカードとして表示。各カードに git ブランチ・変更の有無・最終コミット日時、「実行中」バッジ、「会話履歴あり／新規セッション」の表示。
- **claude 実行**: カードのボタン → そのフォルダーで **新しい WSL ウィンドウ** に claude を起動（履歴があれば `--continue`）。WSL ネイティブ実行のため「フォルダーを信頼」の確認が不要。
- **サーバーコンソール（下部パネル）**: このサーバーのログをリアルタイム（読み取り専用）で表示し、サーバーが動いていることを確認できます。
- **サーバー終了ボタン**: ヘッダーからローカルサーバーを終了します。ウィンドウを閉じても約10秒後に自動終了します(`AUTO_SHUTDOWN=0` で無効)。
- **リモート取得**: アップストリームがあるカードで `git fetch` を実行し、`↓N commits behind` の場合は `git pull --ff-only`。
- **新しいプロジェクト**: `~/projects/<名前>` フォルダーを作成し `git init`。
- **名前変更**: カードの `✏️ 名前変更` → フォルダ名変更 + claude 履歴フォルダも移動(`--continue` 維持) + origin が GitHub なら `gh repo rename` でリポジトリ名・remote URL を更新(gh CLI ログイン必要。失敗時はローカルのみ変更し警告表示)。実行中のプロジェクトは拒否。
- **多言語（i18n）**: ヘッダーで 한국어 · English · 日本語 を切り替え（選択は記憶）。
- **アプリ内ヘルプ**: ヘッダーの `❓ ヘルプ` ボタンまたは `?` キーで使い方モーダル。
- **スキャンフォルダ指定**: `PROJECTS_ROOT` で既定の `~/projects` 以外をスキャン。
- **ポート自動フォールバック**: 既定の `41730` が使用中なら `41731~` に自動移動。

## 仕組み

- ブラウザだけでは PC のプロセスを起動できないため、**WSL 内で動く小さなローカルサーバー**（Express）が代わりに処理します。
- サーバーは `~/projects` をスキャンし、git の状態を取得し、`powershell.exe` で `Start-Process wsl.exe` を呼び出して **新しい WSL ウィンドウ** に claude を起動します。
- サーバーは自身の `stdout/stderr` をキャプチャし、`/ws/console` WebSocket でブラウザ下部パネルに一方向ストリーミングします。

## セキュリティ

- **`127.0.0.1`（localhost）専用バインディング — 外部に公開しないでください。** 認証がなくコマンドを実行するため、外部に公開すると任意のコマンドが実行されるリスクがあります。
- クライアントはプロジェクトの **名前のみ** を送信 → サーバーが `~/projects` 内の実際のパスに再構築・検証（`/`・`..`・改行・NUL は拒否）。
- **個人用ローカルユーティリティ**です。マルチユーザー・リモート利用を想定していません。
