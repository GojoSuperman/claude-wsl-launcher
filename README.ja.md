# Claude WSL Launcher

[한국어](README.md) · [English](README.en.md) · **日本語**

自分のプロジェクトフォルダーを**カードで一覧し、クリック一つでそのフォルダーから Claude Code を起動する**小さなツールです。
毎回ターミナルを開いて `cd なんとか && claude` と打つ代わりに、デスクトップのアイコンをダブルクリックするだけになります。

![ダッシュボード](docs/images/dashboard-en.png)

> **Windows 10/11 専用**です。(macOS・Linux では動作しません。)

---

## なぜ必要なのか

Claude Code は **WSL(Windows の中の Linux)のフォルダーから起動してこそ**、正しく・速く動きます。Windows のエクスプローラーから適当に開いて起動すると、「このフォルダーを信頼しますか?」が繰り返し出て、ファイル操作が **5〜10 倍遅く**なります。

このツールは**常に正しい方法で** claude を起動するので、そうした事情を知らなくても大丈夫です。プロジェクトが複数あればカードで一望でき、昨日の会話の続きから始めることもできます。

## インストール

### まず: あなたはどちらですか?

| 状況 | 進み先 |
|---|---|
| まだ何も入れていない / WSL が何か分からない | 下の **A. ゼロから** |
| すでに WSL で Claude Code を使っている | 下の **B. 2 行で完了** |

> **💡 注意 — Web 版やデスクトップ版の Claude ではインストールできません。**
> claude.ai(Web)や Windows デスクトップアプリの Claude は、**あなたのパソコンにプログラムをインストールする権限がありません。**方法を教えることはできても、代わりに実行することはできません。
> 代わりに実行できるのは、ターミナルで動く **Claude Code(CLI)** です。A の 2 番でそれを先に入れます。

---

### A. ゼロから(まっさらな Windows PC)

自分で行うのは **1・2 番とログイン 1 回**だけです。3 番からは Claude Code に任せられます。

| | どこで | すること |
|---|---|---|
| **1** | **Windows PowerShell(管理者)** | `wsl --install` を実行 → **PC を再起動** → Ubuntu の画面が出たら**ユーザー名とパスワード**を作成 |
| **2** | **Ubuntu ターミナル** | `curl -fsSL https://claude.ai/install.sh \| bash` → そのあと `claude` を実行して**ログイン** |
| **3** | Ubuntu ターミナル | `cd ~ && git clone https://github.com/GojoSuperman/claude-wsl-launcher.git && cd claude-wsl-launcher && claude` |
| **4** | **Claude Code の中で** | **「インストールして」** と入力 — あとは自動で進みます |
| **5** | デスクトップ | 作られたショートカットを**ダブルクリック** |

> **1 番で作ったパスワードは必ず控えておいてください。**あとでソフトを入れるとき(`sudo`)に聞かれます。忘れても再設定できます → [困ったとき](#困ったとき)。

**「Ubuntu ターミナル」とは?** スタートメニューで **「Ubuntu」** を検索してクリックすると出る**黒い画面**です。青い PowerShell の画面とは別物です。プロンプトが `名前@コンピューター:~$` の形なら、正しく入れています。

---

### B. 2 行で完了(WSL と Claude Code がすでにある場合)

Ubuntu ターミナルで:

```bash
cd ~ && git clone https://github.com/GojoSuperman/claude-wsl-launcher.git && cd claude-wsl-launcher
bash scripts/setup.sh
```

`setup.sh` が足りないもの(Node など)を見つけて確認のうえインストールし、プロジェクトフォルダーを選ばせ、デスクトップのショートカットまで作ります。終わったら**ショートカットをダブルクリック**してください。

- このツール自体は `~/projects` のような**プロジェクトフォルダーの中ではなくホーム(`~`)に**置いてください。
- 一段階ずつ確認しながら進めたい場合 → **[セットアップガイド](docs/SETUP.ja.md)**

---

### インストール中に驚かないでください

初めての方が「エラーかな?」と手を止めがちな場面です。**どれも正常です。**

| こう表示されたら | 実際は |
|---|---|
| パスワードを打っても**何も表示されない** | 正常です。Linux はパスワードを画面に出しません。そのまま打って Enter。 |
| `Command 'xxx' not found, but can be installed with:` | エラーではなく**インストール方法の案内**です。示されたコマンドを実行すれば OK。 |
| `Do you want to continue? [Y/n]` | `Y` を打って Enter。 |
| 文字がどんどん流れる | インストール中です。止まるまで待ってください。 |
| 数分かかる | 正常です。ダウンロード中です。 |

## 使い方

デスクトップのショートカットをダブルクリックすると、ブラウザーにダッシュボードが開きます。フォルダー 1 つがカード 1 つです。

| ボタン | すること |
|---|---|
| **claude 起動** | そのフォルダーで claude を新しいウィンドウに起動します。以前の会話があれば**続きから**始まります。 |
| **GitHub 確認 → 取得** | GitHub に新しい変更があるか確認し、あれば自分の PC に取り込みます。 |
| **⬇ 取り込み** | 自分の GitHub リポジトリ一覧から選んで取得します。URL を直接貼り付けても OK。 |
| **+ 新規プロジェクト** | 新しいフォルダーを作ります。 |
| **メモ** | カードごとに 1 行メモ。どのプロジェクトか分からなくなったときに便利です。 |
| **名前変更 / 削除** | フォルダー名を変えたり削除したりします。GitHub リポジトリも一緒に処理できます。 |
| **⟳ アップデート** | このツール自体を最新にします。 |
| **サーバー終了** | 終了します。ウィンドウを閉じるだけでも約 10 秒後に自動で終了します。 |

**色帯の意味**: 🔴 赤 = 確認・取得が必要 · 🟢 緑 = GitHub と同じ(作業して OK) · 🟡 黄 = 自分の変更がまだ GitHub にない

アプリ内の `📖 使い方` ボタン(または `?` キー)で、同じ説明をいつでも見られます。

### GitHub 機能を使うには(任意)

`⬇ 取り込み` とリポジトリ削除には **GitHub CLI のログイン**が一度だけ必要です。**無くても他の機能はすべて動きます。**

Ubuntu ターミナルで:

```bash
sudo apt install gh     # gh が無いと言われたら、まずこれ
gh auth login           # そのあとログイン
```

`gh auth login` はいくつか質問します。矢印キーで選んで Enter: **GitHub.com** → **HTTPS** → **Yes** → **Login with a web browser**。すると 8 文字のコードが出るので、Enter で開くブラウザーにそのコードを貼り付け、**Authorize** を押せば完了です。

## アップデート

ヘッダーの **`⟳ アップデート` ボタン**を押すだけです。確認して、取得して、反映のためにサーバーを終了するところまで案内します。そのあとデスクトップのショートカットをもう一度実行してください。**ターミナルは不要です。**

クローンし直す必要もありません。設定とメモはリポジトリの外にあるので保持され、デスクトップのショートカットもそのまま使えます。

<details>
<summary>ボタンが無い・失敗する場合 — ターミナルからの更新</summary>

ボタンは 2026 年 9 月以降のバージョンにあります。それより前なら、下の方法で**一度だけ**更新すれば、以降はボタンを使えます。

```bash
cd ~/claude-wsl-launcher
git pull
npm install
```

そのあと **ダッシュボードを必ず再起動してください。**

> ⚠️ 起動したまま `git pull` すると、画面のボタンは新しくなりますが**動いているサーバーは古いコードのまま**なので、新機能を押すと「サーバーエラー」になります。故障ではありません。ヘッダーの **[サーバー終了]** を押してから、ショートカットを実行し直してください。

</details>

## 困ったとき

たいていはこれで原因と直し方のコマンドが出ます:

```bash
bash scripts/doctor.sh        # 診断のみ
bash scripts/doctor.sh --fix  # 確認のうえ自動修正
```

| 症状 | 対処 |
|---|---|
| **sudo のパスワードが分からない** | Windows PowerShell で `wsl -u root passwd <自分のユーザー名>` → 新しいパスワードを 2 回入力(画面に出ないのが正常)。 |
| ブラウザーに「接続できません」 | サーバーが止まっています。ショートカットをもう一度ダブルクリック。 |
| `⬇ 取り込み` でエラーが出る | GitHub CLI が無いかログインしていません。画面の案内どおりに進めてください。 |
| ショートカットを押しても何も起きない | Ubuntu ターミナルで `cd ~/claude-wsl-launcher && npm start` を実行してエラーを確認してください。 |
| 初回の起動が遅い | WSL が起きているところです。2 回目からは速くなります。 |

詳しくは → [セットアップガイドのトラブルシューティング](docs/SETUP.ja.md#6-トラブルシューティング)

### 動作要件

| 必須 | 理由 |
|---|---|
| **Windows 10/11 + WSL2** | `wsl.exe`・`cmd.exe` でウィンドウを開くため → macOS・ネイティブ Linux は非対応 |
| WSL 内の **Node.js 20 以上** | サーバーの実行(無ければ `setup.sh` が nvm でのインストールを提案) |
| WSL 内の **Claude Code CLI** | このツールが起動する対象(無ければ `setup.sh` がインストールを提案) |

| 任意 | 用途 |
|---|---|
| **GitHub CLI(`gh`)** ログイン済み | 取り込み、リポジトリ削除、公開/非公開バッジ、名前変更時に GitHub リポジトリ名も変更 |

ディストリビューション名・ホーム・デスクトップのパスは**実行時に検出**するため、PC ごとの設定は不要です。

### 全機能

- **カード一覧**: フォルダーごとに git ブランチ・変更の有無・最終コミット時刻、「実行中」バッジ、「履歴あり / 新規セッション」を表示。
- **claude 起動**: そのフォルダーで**新しい WSL ウィンドウ**に claude(履歴があれば `--continue`)。WSL ネイティブ起動なので「このフォルダーを信頼しますか?」の再質問が出ません。
- **リモート確認 / 取得**: `git fetch` 後、遅れていれば `git pull --ff-only`。
- **新規プロジェクト**: `~/projects/<名前>` を作成して `git init`。
- **GitHub から取り込み**: 自分のリポジトリ一覧を検索してクローン(gh ログインが必要)。取得済みは区別表示。URL 直接入力も可能。
- **プロジェクトの削除**: ローカルフォルダーをゴミ箱へ移動し、必要なら **GitHub リポジトリも同時に削除**(チェックボックス、gh ログインが必要)。実行中のプロジェクトとこのツール自身は削除不可。GitHub の削除が失敗した場合はローカルも保持。
- **メモ**: カードごとに 1 行のメモ(`~/.local/state/project-launcher/notes.json` に保存)。
- **プロジェクト名変更**: フォルダー名を変更し、claude の履歴フォルダーも一緒に移動(`--continue` 維持)。origin が GitHub なら `gh repo rename` でリポジトリ名と remote URL も更新。
- **名前の規則**: 英数字・`-`・`_`・`.` のみ(GitHub リポジトリの規則)。
- **ランチャー自体の更新**: `⟳ アップデート` → 確認 → `git pull --ff-only` + `npm install` → 反映のための終了。手元の変更が更新対象のファイルと重なる場合や履歴が分岐している場合は**何も変更せず**理由を表示。
- **GitHub 公開/非公開バッジと切替**: バッジをクリックすると確認後に `gh repo edit --visibility` で切り替え。
- **サーバーコンソール(下部パネル)**: このサーバーのログをリアルタイム表示(読み取り専用)。
- **自動停止**: ダッシュボードのウィンドウを閉じると約 10 秒後にサーバーが自動停止(`AUTO_SHUTDOWN=0` で無効)。
- **ライト/ダークテーマ**、**多言語**(한국어 · English · 日本語)、**アプリ内ヘルプ**(`?` キー)。
- **プロジェクトフォルダーの選択・変更**: 優先順位は `PROJECTS_ROOT` > 設定ファイル(`~/.config/project-launcher/config.json`)> `~/projects`。
- **ポート自動フォールバック**: `41730` が使用中なら `41731`〜`41739`。`PORT=5000 npm start` で指定可能。

### なぜこの方式か

claude は **WSL ネイティブのパス**(`~/projects/...`、ext4)から起動してこそ正しく・速く動きます。Windows エクスプローラーで `\\wsl.localhost\...` に入ってそこから起動すると罠にはまります:

- 「このフォルダーを信頼しますか?」が繰り返し出る
- claude の Bash が **Windows の Git Bash** で動き、Linux の `node_modules` バイナリと衝突する
- セッションログが Windows 側(`C:\...`)に別途たまる
- 境界をまたぐファイル I/O(`npm install`・`git status` など)が **5〜10 倍遅い**

### 仕組み

- ブラウザーだけでは PC のプロセスを起動できないため、**WSL 内で動く小さなローカルサーバー**(Express)が代わりに行います。
- サーバーはプロジェクトフォルダーをスキャンし、git 状態を取得し、`cmd.exe /c start` で `wsl.exe` を呼んで**新しい WSL ウィンドウ**に claude を起動します。
- サーバーは自身の `stdout/stderr` を `/ws/console` WebSocket に流して下部パネルに表示します。その接続がすべて切れると猶予後に自動停止します。

### セキュリティ

- **`127.0.0.1`(localhost)専用バインド — 外部に公開しないでください。** 認証がなくコマンドを実行するため、外部に開くと任意コマンド実行の危険があります。
- クライアントはプロジェクト**名のみ**送信 → サーバーがプロジェクトフォルダー内の実パスに再構成・検証(`/`・`..`・改行・NUL を拒否)。
- **個人用ローカルユーティリティ**です。マルチユーザー・リモート用途ではありません。
