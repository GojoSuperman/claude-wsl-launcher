# セットアップガイド(初めての方向け)

[한국어](SETUP.ko.md) · [English](SETUP.en.md) · **日本語**

順序は **WSL2 の確認 → ツールの取得 → `setup.sh` を一度 → 起動** です。コマンドはすべて **WSL(Ubuntu)ターミナル**に入力します。
急ぐ場合は [README のクイックスタート](../README.ja.md#クイックスタート)の 2 行で十分です。このガイドは各段階で何を確認するかを説明します。

---

## ゼロから起動まで — 何もない Windows PC で 5 ステップ (Claude Code にインストールを任せる)

何も入っていない PC ならこの順序が最短です。人が行うのは **1・2 とログイン 1 回**だけで、残りは Claude Code がやります。

| 手順 | どこで | やること |
|---|---|---|
| 1 | **Windows PowerShell(管理者)** | `wsl --install` → 再起動 → Ubuntu 初回起動でユーザー名・パスワードを作成 |
| 2 | **Ubuntu ターミナル** | Claude Code をインストール: `curl -fsSL https://claude.ai/install.sh \| bash`(Node 不要)→ `claude` を一度実行して**ログイン** |
| 3 | Ubuntu ターミナル | `cd ~ && git clone https://github.com/GojoSuperman/claude-wsl-launcher.git && cd claude-wsl-launcher && claude` |
| 4 | **Claude Code の中で** | **「インストールして」** — README を読んで `bash scripts/setup.sh` を実行します。キーボード入力が無い環境なので自動で全部「はい」。Node/nvm が無くてもインストールし、作業フォルダー(`~/projects`)を作り、デスクトップのショートカットまで作ります |
| 5 | デスクトップ | ショートカットをダブルクリック |

- 3 の clone も Claude Code に任せられます: `cd ~ && claude` でホームから起動し「この URL をクローンしてインストールして」。ランチャーは作業フォルダー `~/projects` の**中ではなくホーム**に置いてください。
- 以下の 0〜7 は同じ手順を一段階ずつ確認しながら手で行う場合の説明です。

---

## 0. このツールは何? / 必要なもの

`~/projects` 内のプロジェクトをウェブ画面(ダッシュボード)で見て、ボタン一つでそのフォルダーから **Claude Code** を新しいターミナルウィンドウで起動する個人用ローカルツールです。

| 必要なもの | 理由 | 無い場合 |
|---|---|---|
| **Windows 10/11 + WSL2** | `wsl.exe`・`cmd.exe` でウィンドウを開く → **Mac・通常の Linux では動きません** | 1 でインストール |
| WSL 内の **Node.js 20 以上** | サーバーの実行 | `setup.sh` が nvm でのインストールを提案 |
| WSL 内の **Claude Code CLI**(`claude`) | このツールが起動する対象 | `setup.sh` がインストールを提案 |
| (任意)**GitHub CLI**(`gh`)ログイン済み | **GitHub からの取り込み**、リポジトリの削除、公開/非公開バッジ、「プロジェクト名変更」で GitHub リポジトリ名も変更 | 他の機能は無くても動作(取り込み・削除のみ不可、バッジは `?`) |

## 1. WSL2 があるか確認(無ければインストール)

**Windows PowerShell**(WSL ではない)を開いて:

```powershell
wsl --version
```

- バージョンが表示される → WSL2 あり。次へ。
- エラーになる → 管理者 PowerShell で `wsl --install` を実行し、**PC を再起動**、Ubuntu の初期設定(ユーザー名・パスワード)を済ませます。

> 💡 **「WSL(Ubuntu)ターミナル」とは?** スタートメニューで **「Ubuntu」** を検索してクリックすると開く黒いウィンドウです。プロンプトが `名前@コンピューター:~$` の形なら正しく入れています。PowerShell(`PS C:\>`)・コマンドプロンプトとは別のウィンドウです。PowerShell で `wsl` と打っても同じ Ubuntu に入れますが、その場合 `/mnt/c/...`(Windows のフォルダー)から始まることがあるので `cd ~` で Linux のホームへ移動してください。

ここからは **WSL(Ubuntu)ターミナル**で進めます。

---

## 2. ツールの取得

> ⚠️ **必ず WSL ターミナルの中でクローンしてください。** PowerShell・エクスプローラーからクローンすると `.sh` が Windows の改行(CRLF)で保存され、スクリプトが `set: pipefail: invalid option name` で失敗します。(`setup.sh` がこれも点検・修正します。)

```bash
cd ~                 # ツールは作業フォルダーの外に(ホームなど — ~/projects の中には置かない)
git clone https://github.com/GojoSuperman/claude-wsl-launcher.git
cd claude-wsl-launcher
```

---

## 3. `setup.sh` を一度

```bash
bash scripts/setup.sh
```

何をするか:

| # | 点検 | 問題があれば |
|---|---|---|
| 1 | WSL 内か、`cmd.exe`・`wsl.exe` にアクセスできるか | 原因と対処を案内 |
| 2 | Node.js 20 以上 | 「nvm でインストールしますか? [Y/N]」 |
| 3 | `claude` が **Linux 側(nvm)** にあるか — ショートカットが実際に探す方法そのまま | 「インストールしますか? [Y/N]」(`npm install -g @anthropic-ai/claude-code`) |
| 4 | (任意)`gh` のログイン状態 | 案内のみ |
| 5 | `scripts/*.sh` の改行が LF か | 「直しますか? [Y/N]」 |
| 6 | 依存関係(`node_modules`) | 無ければ `npm install` |
| 6.5 | **作業フォルダー**: WSL 内の `~/projects`(固定) | 無ければ作成。ホーム配下の別の場所に git リポジトリのフォルダーがあれば一覧で表示し、ダッシュボードの ⬇ 取り込みで移すよう案内 |
| 7 | デスクトップのショートカット | 「作りますか? [Y/N]」 |

- すべての質問はそのまま Enter で「いいえ」です。飛ばしたものは後で `bash scripts/setup.sh` を再実行すれば続きから行えます。
- すでに使っているプロジェクトフォルダー(`~/dev`、`~/work` など)があれば、リポジトリ数付きで知らせます。ダッシュボードの **[⬇ 取り込み] → 🐧 WSL** タブで `~/projects` へ移してください。
- 質問なしで終えるには(AI エージェント・スクリプト): `bash scripts/setup.sh --yes` — すべて「はい」。キーボード入力が無い環境では `--yes` を付けなくても自動的にこのモードになります。
- ショートカット名を変える: `SHORTCUT_NAME='マイランチャー' bash scripts/setup.sh`(既定 `Claude WSL Launcher`)。
- 最後に `✅` と接続先 URL が表示されれば完了です。

> プロジェクトは**ツールの置き場所とは無関係に** WSL 内の**作業フォルダー `~/projects`** で作業します(固定)。各サブフォルダーがカードになります。
> Windows のフォルダー(デスクトップ・ドキュメントなど)で直接作業すると遅く、改行コードの問題が起きるため固定しました。別の場所のプロジェクトはダッシュボードの **[⬇ 取り込み]** で移してください。

## 4. 起動

**デスクトップのショートカットをダブルクリック**すると:

- サーバーを**バックグラウンド**で起動し、**ブラウザだけ**を開きます(余分なターミナルウィンドウなし)。Chrome があれば**アドレスバーのないアプリ風ウィンドウ**、無ければ既定ブラウザのタブで開きます。
- サーバーの起動に**失敗したときだけ**ターミナルウィンドウが出てログを表示します。
- すでに起動していれば、再起動せずブラウザだけ開きます。

ターミナルから直接起動する場合:

```bash
npm start       # 最後に「프로젝트 런처: http://127.0.0.1:41730」が出れば成功
```

- ポートが使用中なら 41731〜41739 に自動フォールバックするので、ログに出た実際のアドレスを開きます。指定: `PORT=5000 npm start`
- 作業フォルダーは `~/projects` に固定です。別の場所のプロジェクトは **[⬇ 取り込み]** で移します。
- **停止**: ダッシュボードのウィンドウを閉じると約 10 秒後にサーバーが**自動停止**します。すぐ止めるにはヘッダーの **[サーバー停止]** ボタンかターミナルで `Ctrl+C`。(自動停止を無効にするには `AUTO_SHUTDOWN=0 npm start`)

## 5. 使い方

| ボタン | 動作 |
|---|---|
| **[claude 起動]** | そのフォルダーで**新しい WSL ウィンドウ**に claude。会話履歴があれば続き(`--continue`)、無ければ新規セッション |
| **[リモート確認]** → **[取得]** | `git fetch` 後、遅れていれば `git pull --ff-only`(upstream のあるカードにのみ表示) |
| **[+ 新規プロジェクト]** | `~/projects/<名前>` を作成し `git init` |
| **[⬇ 取り込み]** | 3 つのタブから選んで作業フォルダーへ。**GitHub**: リポジトリ一覧を検索してクローン(gh ログインが必要、取得済みは区別表示、一覧を読み込めない場合は **URL 直接入力**)。**💻 PC**: デスクトップ・ドキュメント・ダウンロード・ドライブのフォルダーを**コピー**(元は保持、`node_modules` は除外)。**🐧 WSL**: ホームの別のフォルダーを**移動**。claude の会話履歴とフォルダーごとの claude 設定も一緒に移り、`.git` はそのままなので GitHub との連携は保たれます |
| カードの **[削除]** | ローカルフォルダーをゴミ箱へ移動。チェックボックスで **GitHub リポジトリも削除**(gh ログインが必要)。実行中のプロジェクトとこのツール自身のフォルダーは削除不可。GitHub の削除が失敗した場合はローカルも保持 |
| **🗑 ゴミ箱 (n)** | 作業フォルダーの横(削除したものがあるときだけ)。削除したプロジェクトを**元に戻す**か**完全に削除**。Windows のごみ箱とは別 |
| カードの **👑 / 👥 / 👀 バッジ** | チームプロジェクト(共同リポジトリ)での自分の役割。**GitHub 確認**で main・PR 基準のやることを帯で表示、**ⓘ** で詳しい状態と claude に伝える言葉(コピー)|
| **[✨ 新機能]** | 更新で変わった機能の紹介。更新後に初めて開いたときは自動で表示 |
| カードの **[メモ]** | カードごとに 1 行のメモ(`~/.local/state/project-launcher/notes.json` に保存) |
| **[✏️ プロジェクト名変更]** | フォルダー名を変更し、claude の履歴フォルダーとフォルダーごとの claude 設定も一緒に移動。origin が GitHub なら `gh repo rename` でリポジトリ名と remote URL も更新(gh ログインが必要。失敗時はローカルのみ変更し警告)。実行中のプロジェクトとこのツール自身のフォルダーではボタン無効 |
| カードの **GitHub 行** | origin リポジトリ(`owner/repo`)と**公開/非公開**バッジ。gh 未ログインなら `?`。バッジをクリックすると確認後に公開↔非公開を切替(リポジトリの管理者権限が必要) |
| **自動 · ☀️ · 🌙** | ライト/ダークテーマ。自動 = Windows 設定に従う(記憶されます) |
| **[⟳ アップデート]** | ランチャー自体を最新に。確認 → 取得 → 反映のための終了までを 1 つのモーダルで。手元の変更が更新対象のファイルと重なる場合や履歴が分岐している場合は何も変更せず理由を表示 |
| **[❓ ヘルプ]** / `?` キー | 使い方モーダル |
| 下部の**サーバーコンソール** | このサーバーのログ(読み取り専用)。▾ で折りたたみ/展開 |

- **名前の規則**: 新規作成・名前変更とも**英数字・`-`・`_`・`.` のみ**(GitHub リポジトリの規則)。それ以外を入力すると案内が出て中止します。
- 名前変更の前に「他の claude ウィンドウでこのフォルダーを編集中でないか」の確認が一度出ます。別フォルダーから起動した claude がこのフォルダーを編集している場合は自動検出されません。
- 別の PC でも使うには、その PC で 2・3 をもう一度行ってください。コードは git で取得できますが、Node・claude のインストールとショートカットは PC ごとに必要です。

### 複数の Claude アカウントを使う(任意)

カードの起動ボタン横の **▾** → **＋ アカウント追加** を押すとログイン用のウィンドウが開きます。そこで別の Claude アカウントでログインして閉じると、▾ メニューにそのアカウントのメールアドレスが表示されます。

- 会話履歴・指示(CLAUDE.md)・設定・プラグイン・スキル・MCP は既定アカウントと共有し、ログインと使用量だけが別です。どのアカウントで開いても同じプロジェクトを「続きから実行」できます。
- プロジェクトごとに最後に使ったアカウントを記憶します。起動ボタンとターミナルのタブにアカウント名が表示されます。
- **⚙ アカウント管理** で別名を付けたり、一覧から外したりできます(アカウントフォルダ `~/.claude-acct-N` とログイン情報は削除しません)。

## 6. トラブルシューティング

まずこれを実行してください。ほとんどはここで原因とコマンドが分かります:

```bash
bash scripts/doctor.sh        # 診断のみ
bash scripts/doctor.sh --fix  # 確認のうえ自動修正
```

doctor で捕まえられないもの:

| 症状 | 対処 |
|---|---|
| ブラウザで「接続できません」 | サーバーが起動していないか自動停止した。ショートカットを再度ダブルクリック、または `npm start`。 |
| `claude 起動` を押してもウィンドウが出ない / "spawn cmd.exe ENOENT" | PATH の問題。WSL ターミナルから `npm start`(ログインシェル)でサーバーを起動してみてください。 |
| ポート使用中(EADDRINUSE) | すでにサーバーが起動中。[サーバー停止] するか `PORT=5000 npm start`。 |
| 更新後にカードが見えない(以前は別のプロジェクトフォルダーを選んでいた) | 作業フォルダーが `~/projects` に固定されました。**[⬇ 取り込み] → 🐧 WSL / 💻 PC** タブで以前のフォルダーを探してプロジェクトを取り込んでください。**✨ 新機能**ウィンドウの一番上に以前のフォルダーの場所が表示されます。 |
| ショートカットが古い動作をする / 動かない | `bash scripts/install-shortcut.sh` で再作成。 |
| 名前変更後に「GitHub の名前変更に失敗」の警告 | ローカルは変更済み。`gh auth login` 後に再試行するか、GitHub ウェブで名前を変えて `git remote set-url origin <新しい URL>`。 |

## 7. セキュリティを一行で

このサーバーは **自分の PC(localhost)専用**で認証がありません。**外部に公開しないでください**(ポートフォワーディング・`0.0.0.0` バインド禁止)。個人用ローカルツールとしてのみ使ってください。

## 付録. 手動でインストールしたい場合

`setup.sh` を使わずに自分で行う場合のコマンドです。

**WSL 環境の確認**

```bash
echo "ディストリ: $WSL_DISTRO_NAME"   # 例: Ubuntu-24.04
echo "ユーザー: $(whoami)"            # 例: alice
echo "ホーム: $HOME"                  # 例: /home/alice
```

(これらは自動検出されるため、どこにも入力しません。)

**Node.js**

```bash
node -v    # v20.x 以上なら OK。無い/古い場合:
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# ターミナルを閉じて開き直してから:
nvm install --lts
```

**Claude Code CLI**

```bash
claude --version   # 無ければ (どちらか):
curl -fsSL https://claude.ai/install.sh | bash   # 公式インストーラー — Node 不要 (推奨)
npm install -g @anthropic-ai/claude-code          # または npm (Node が必要)
# インストール後 claude を一度実行してログイン。最新のインストール方法は Claude Code 公式ドキュメントを優先してください。
```

**依存関係・実行・ショートカット**

```bash
npm install
npm start                               # または
bash scripts/install-shortcut.sh        # デスクトップのショートカット
```

**改行が壊れたとき**(`set: pipefail: invalid option name`): WSL 内で `sed -i 's/\r$//' scripts/*.sh`、または WSL ターミナルからクローンし直してください。
