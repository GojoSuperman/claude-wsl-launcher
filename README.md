# Claude WSL Launcher

**한국어** · [English](README.en.md) · [日本語](README.ja.md)

내 프로젝트 폴더들을 **카드로 보여주고, 클릭 한 번으로 그 폴더에서 Claude Code를 띄워주는** 작은 도구입니다.
매번 터미널을 열고 `cd 어쩌고 && claude` 를 치는 대신, 바탕화면 아이콘을 더블클릭하면 됩니다.

![대시보드](docs/images/dashboard-ko.png)

> **Windows 10/11 전용**입니다. (맥·리눅스에서는 동작하지 않습니다.)

---

## 이게 왜 필요한가요?

Claude Code는 **WSL(윈도우 안의 리눅스) 폴더에서 띄워야** 제대로, 그리고 빠르게 동작합니다. 윈도우 탐색기에서 아무 데나 열고 실행하면 "이 폴더를 신뢰하시겠습니까?" 가 반복되고, 파일 작업이 **5~10배 느려집니다.**

이 도구는 **항상 올바른 방식으로** claude를 띄워주기 때문에, 그런 걸 몰라도 됩니다. 프로젝트가 여러 개면 카드로 한눈에 보이고, 어제 하던 대화를 이어서 시작할 수도 있습니다.

## 설치하기

### 먼저: 내 PC는 어느 쪽인가요?

| 내 상황 | 어디로 |
|---|---|
| 컴퓨터에 아무것도 없다 / WSL이 뭔지 모르겠다 | 아래 **A. 처음부터** |
| 이미 WSL에서 Claude Code를 쓰고 있다 | 아래 **B. 두 줄이면 끝** |

> **💡 잠깐 — 웹 클로드나 윈도우 클로드 앱으로는 설치할 수 없습니다.**
> claude.ai(웹)나 윈도우 데스크탑 앱의 클로드는 **내 컴퓨터에 프로그램을 설치할 권한이 없습니다.** 설치 방법을 알려줄 수는 있어도 대신 해주지는 못합니다.
> 대신 설치해 줄 수 있는 건 터미널에서 도는 **Claude Code(CLI)** 입니다. 아래 A의 2번에서 그것부터 깝니다.

---

### A. 처음부터 (빈 Windows PC)

사람이 직접 하는 건 **1·2번과 로그인 한 번**뿐입니다. 3번부터는 Claude Code에게 맡기면 됩니다.

| | 어디서 | 할 일 |
|---|---|---|
| **1** | **Windows PowerShell (관리자)** | `wsl --install` 입력 → **PC 재부팅** → 우분투 창이 뜨면 **사용자 이름과 비밀번호**를 만듭니다 |
| **2** | **우분투 터미널** | `curl -fsSL https://claude.ai/install.sh \| bash` → 그다음 `claude` 를 실행해 **로그인** |
| **3** | 우분투 터미널 | `cd ~ && git clone https://github.com/GojoSuperman/claude-wsl-launcher.git && cd claude-wsl-launcher && claude` |
| **4** | **Claude Code 안에서** | **"설치해줘"** 라고 입력 — 나머지는 알아서 합니다 |
| **5** | 바탕화면 | 생긴 단축키를 **더블클릭** |

> **1번에서 만든 비밀번호를 꼭 적어두세요.** 나중에 프로그램을 설치할 때(`sudo`) 물어봅니다. 잊어버려도 다시 정할 수 있습니다 — [아래 문제 해결](#설치하다-막혔을-때) 참고.

**"우분투 터미널"이 뭔가요?** 시작 메뉴에서 **"Ubuntu"** 를 검색해 클릭하면 뜨는 **검은 창**입니다. 파란색 PowerShell 창과는 다릅니다. 프롬프트가 `이름@컴퓨터:~$` 모양이면 제대로 들어온 것입니다.

---

### B. 두 줄이면 끝 (WSL·Claude Code가 이미 있다면)

우분투 터미널에서:

```bash
cd ~ && git clone https://github.com/GojoSuperman/claude-wsl-launcher.git && cd claude-wsl-launcher
bash scripts/setup.sh
```

`setup.sh` 가 빠진 것(Node 등)을 찾아 물어보고 설치하고, 프로젝트 폴더를 고르게 한 뒤, 바탕화면 단축키까지 만들어 줍니다. 끝나면 **단축키를 더블클릭**하세요.

- 이 도구 자체는 `~/projects` 같은 **프로젝트 폴더 안이 아니라 홈(`~`)에** 두세요.
- 한 단계씩 확인하며 설치하고 싶다면 → **[설치 가이드](docs/SETUP.ko.md)**

### 설치 중에 놀라지 마세요

처음 하는 분들이 자주 "에러인가?" 하고 멈추는 지점들입니다. **전부 정상입니다.**

| 화면에 이런 게 나오면 | 사실은 |
|---|---|
| 비밀번호를 치는데 **아무 글자도 안 보임** | 정상입니다. 리눅스는 비밀번호를 화면에 표시하지 않습니다. 그냥 치고 Enter. |
| `Command 'xxx' not found, but can be installed with:` | 에러가 아니라 **설치 방법 안내**입니다. 알려주는 명령을 그대로 실행하면 됩니다. |
| `Do you want to continue? [Y/n]` | `Y` 를 치고 Enter. |
| 글자가 주르륵 올라감 | 설치 중입니다. 멈출 때까지 기다리세요. |
| 설치가 몇 분 걸림 | 정상입니다. 인터넷에서 받아오는 중입니다. |

## 쓰는 법

바탕화면 단축키를 더블클릭하면 브라우저에 대시보드가 열립니다. 폴더 하나가 카드 하나입니다.

| 버튼 | 하는 일 |
|---|---|
| **claude 실행** | 그 폴더에서 claude를 새 창에 띄웁니다. 전에 하던 대화가 있으면 **이어서** 시작합니다. |
| **GitHub 확인 → 받기** | GitHub에 새 변경이 있는지 보고, 있으면 내 PC로 가져옵니다. |
| **⬇ 가져오기** | 내 GitHub 저장소 목록에서 골라 받아옵니다. 주소를 직접 붙여넣어도 됩니다. |
| **+ 새 프로젝트** | 새 폴더를 만듭니다. |
| **메모** | 카드마다 한 줄 메모. 어떤 프로젝트인지 헷갈릴 때 좋습니다. |
| **이름 변경 / 삭제** | 폴더 이름을 바꾸거나 지웁니다. GitHub 저장소까지 함께 처리할 수 있습니다. |
| **⟳ 업데이트** | 이 도구 자체를 최신으로 만듭니다. |
| **서버 종료** | 끕니다. 그냥 창을 닫아도 10초 뒤 알아서 꺼집니다. |

**색 띠가 알려주는 것**: 🔴 빨강 = 확인/받기가 필요함 · 🟢 초록 = GitHub와 같음(작업해도 안전) · 🟡 노랑 = 내 변경이 아직 GitHub에 없음

화면 안에서 `❓ 사용법` 버튼(또는 `?` 키)을 누르면 같은 설명을 언제든 볼 수 있습니다.

### GitHub 기능을 쓰려면 (선택)

`⬇ 가져오기` 와 저장소 삭제는 **GitHub CLI 로그인**이 한 번 필요합니다. **안 해도 나머지 기능은 전부 그대로 동작합니다.**

우분투 터미널에서:

```bash
sudo apt install gh     # 없다고 나오면 먼저 이것
gh auth login           # 그다음 로그인
```

`gh auth login` 은 몇 가지를 물어봅니다. 화살표로 고르고 Enter 하세요: **GitHub.com** → **HTTPS** → **Yes** → **Login with a web browser**. 그러면 8자리 코드가 나오는데, Enter를 누르면 열리는 브라우저에 그 코드를 붙여넣고 **Authorize** 를 누르면 끝입니다.

## 업데이트

**헤더의 `⟳ 업데이트` 버튼**을 누르면 끝입니다. 확인하고, 받고, 적용을 위해 서버를 끄는 것까지 안내해 줍니다. 그다음 바탕화면 단축키를 다시 실행하세요. **터미널은 필요 없습니다.**

다시 클론할 필요도 없습니다. 설정과 메모는 저장소 바깥에 있어서 그대로 유지되고, 바탕화면 단축키도 그대로 씁니다.

<details>
<summary>버튼이 안 보이거나 실패할 때 — 터미널로 업데이트</summary>

버튼은 2026년 9월 이후 버전부터 있습니다. 그 전 버전이라면 **한 번만** 아래로 업데이트하면, 이후로는 버튼을 쓸 수 있습니다.

```bash
cd ~/claude-wsl-launcher
git pull
npm install
```

그다음 **대시보드를 반드시 껐다 켜세요.**

> ⚠️ 켜놓은 채로 `git pull` 만 하면, 화면의 버튼은 새것으로 바뀌는데 **실행 중인 서버는 옛 코드 그대로**라 새 기능을 누를 때 "서버 오류" 가 납니다. 고장이 아닙니다. 헤더의 **[서버 종료]** 를 누르고 단축키를 다시 실행하면 해결됩니다.

</details>

## 설치하다 막혔을 때

대부분은 이것으로 원인과 해결 명령이 나옵니다:

```bash
bash scripts/doctor.sh        # 검사만
bash scripts/doctor.sh --fix  # 물어보고 자동으로 고침
```

| 증상 | 해결 |
|---|---|
| **sudo 비밀번호를 모르겠다** | 윈도우 PowerShell에서 `wsl -u root passwd <내 사용자이름>` → 새 비밀번호를 두 번 입력(화면에 안 보이는 게 정상). |
| 브라우저에 "연결할 수 없음" | 서버가 꺼진 것입니다. 단축키를 다시 더블클릭하세요. |
| `⬇ 가져오기` 를 눌렀더니 오류 | GitHub CLI가 없거나 로그인이 안 된 것입니다. 화면에 뜨는 안내대로 하시면 됩니다. |
| 단축키를 눌러도 아무 일도 안 일어남 | 우분투 터미널에서 `cd ~/claude-wsl-launcher && npm start` 를 실행해 오류 메시지를 확인하세요. |
| 첫 실행이 느림 | WSL이 처음 깨어나는 중입니다. 두 번째부터는 빨라집니다. |

더 자세한 표 → [설치 가이드의 문제 해결](docs/SETUP.ko.md#6-문제-해결)

### 요구사항

| 필수 | 이유 |

| WSL 안에 **Claude Code CLI** | 이 도구가 띄우는 대상 (`setup.sh` 가 없으면 설치 제안) |

|---|---|
| **GitHub CLI (`gh`)** 로그인 | 가져오기·저장소 삭제·공개/비공개 배지·이름 변경 시 GitHub 저장소 이름까지 변경 |

distro 이름·홈·바탕화면 경로는 **런타임에 감지**하므로 PC 마다 설정할 것이 없습니다.

### 전체 기능

- **카드 목록**: 폴더마다 git 브랜치·변경 여부·마지막 커밋 시각, "실행 중" 배지, "대화 이력 있음/새 세션" 표시.
- **claude 실행**: 그 폴더에서 **새 WSL 창**에 claude (이력 있으면 `--continue`). WSL 네이티브 실행이라 "폴더 신뢰" 재질문이 없음.
- **원격 확인 / 받기**: `git fetch` 후 뒤처졌으면 `git pull --ff-only`.
- **새 프로젝트**: `~/projects/<이름>` 폴더 생성 + `git init`.
- **GitHub 에서 가져오기**: 내 저장소 목록 검색 후 클론(gh 로그인 필요). 이미 받은 것은 구분 표시. URL 직접 입력도 가능.
- **프로젝트 삭제**: 로컬 폴더를 휴지통으로. 체크박스로 GitHub 저장소까지 삭제. 실행 중인 프로젝트와 이 도구 자신은 불가. GitHub 삭제가 실패하면 로컬도 보존.
- **메모**: 카드마다 한 줄 메모(`~/.local/state/project-launcher/notes.json`).
- **프로젝트 이름 변경**: 폴더 + claude 대화 이력 폴더 동시 이동(`--continue` 유지). origin 이 GitHub 면 `gh repo rename` 으로 저장소 이름·remote URL 까지 갱신.
- **이름 규칙**: 영문·숫자·`-`·`_`·`.` 만 허용(GitHub 저장소 규칙, 한글 불가).
- **런처 자체 업데이트**: `⟳ 업데이트` → 확인 → `git pull --ff-only` + `npm install` → 적용을 위한 종료. 고친 파일이 업데이트와 겹치거나 이력이 갈라졌으면 **아무것도 바꾸지 않고** 이유 표시.
- **GitHub 공개/비공개 표시·전환**: 배지 클릭 → 확인 후 `gh repo edit --visibility`.
- **서버 콘솔(하단 패널)**: 이 서버의 로그를 실시간(읽기 전용)으로 표시.
- **자동 종료**: 대시보드 창을 닫으면 약 10초 뒤 서버 종료(`AUTO_SHUTDOWN=0` 으로 끔).
- **라이트/다크 테마**, **다국어**(한국어·English·日本語), **인앱 도움말**(`?` 키).
- **프로젝트 폴더 선택·변경**: 우선순위는 `PROJECTS_ROOT` > 설정 파일(`~/.config/project-launcher/config.json`) > `~/projects`.
- **포트 자동 폴백**: `41730` 사용 중이면 `41731~41739`. `PORT=5000 npm start` 로 지정 가능.

### 왜 이 방식인가

claude 는 **WSL 네이티브 경로**(`~/projects/...`, ext4)에서 띄워야 제대로·빠르게 동작합니다. 윈도우 탐색기로 `\\wsl.localhost\...` 에 들어가 거기서 실행하면:

- "이 폴더를 신뢰?" 재질문이 반복됨
- claude 의 Bash 가 **Windows Git Bash** 로 돌아 리눅스 `node_modules` 바이너리와 충돌
- 세션 로그가 Windows 쪽(`C:\...`)에 따로 쌓임
- 경계를 넘는 파일 I/O(`npm install`·`git status` 등)가 **5~10배 느림**

### 작동 방식

- 브라우저만으론 PC 프로세스를 못 띄우므로, **WSL 안에서 도는 작은 로컬 서버**(Express)가 대신합니다.
- 서버는 프로젝트 폴더를 스캔하고 git 상태를 조회하며, `cmd.exe /c start` 로 `wsl.exe` 를 호출해 **새 WSL 창**에 claude 를 띄웁니다.
- 서버는 자신의 `stdout/stderr` 를 `/ws/console` WebSocket 으로 하단 패널에 흘려보냅니다. 연결이 모두 끊기면 유예 후 자동 종료합니다.

### 보안

- **`127.0.0.1`(localhost) 전용 바인딩 — 외부에 노출하지 마세요.** 인증이 없고 명령을 실행하므로, 외부에 열면 임의 명령 실행 위험이 있습니다.
- 클라이언트는 프로젝트 **이름만** 전송 → 서버가 프로젝트 폴더 안의 실제 경로로 재구성·검증(`/`·`..`·개행·NUL 거부).
- **개인 로컬 유틸리티**입니다. 멀티유저·원격 사용 용도가 아닙니다.
